# 檢視器的影格與時間同步

## 原因與實際重現

2026-10-23 的截圖反映了檢視器定位錯誤。原始分析以順序解碼的影格編號記錄 STAGE/OCR；檢視器卻使用 OpenCV `CAP_PROP_POS_FRAMES` 直接跳轉，並以 `frame / average_fps` 顯示時間。對含不均勻時間戳或時間間隔的 MP4，這兩個假設都不可靠。此定位方式在改版前的 GUI 原始碼已存在，配色變更沒有改寫分析資料，但先前只用固定 FPS 測試，未驗出這類錯誤。

案例 A 的第 2287 幀從頭順序解碼後可見 Capsulorhexis，實際呈現時間 78.665 秒；原顯示時間約 76.40 秒，直接按幀號跳轉得到的畫面也不同。影片最大相鄰 PTS 間隔約 2.465 秒。兩部截圖影片共抽查 46 個位置，舊定位有 30 個位置的像素與順序解碼不一致，修正後全部完全相同。

另外，停在 STAGE 模式切換影片時，表格在新 `stage_analysis.json` 尚未載入前刷新，之後只刷新了時間軸。這會造成時間軸有資料、表格卻空白。現在會在階段資料與 OCR 快取載入完成後重建階段表格。

## 同一套時間座標

- 影格編號仍指順序解碼的第幾幀，與既有分析 JSON 相同。
- `utils/indexed_video.py` 建立呈現時間戳（PTS）索引。只有具備可靠、唯一且與宣告影格數一致的一對一封包資訊時才使用封包索引，否則改由解碼影格建立索引。
- 實際畫面仍使用既有 OpenCV 4.11 解碼。先跳至目標之前，再向前解碼、逐筆驗證 PTS，直到精確對應目標影格。不能確認時顯示錯誤並清除舊畫面，避免把錯誤畫面標成成功跳轉。
- 右側事件、播放滑桿、時間軸段落起訖與紅色位置標記使用相同的實際 PTS 秒數。點擊時間軸則直接跳至該事件的整數幀號，並切換至對應區域。
- 拖曳滑桿只在底列顯示「定位預覽」；放開並成功解碼後，才更新已顯示畫面的幀號與時間。持續播放也依相鄰 PTS 的時間差排程。

PyAV 僅用於索引／媒體時間戳存取，定位的 seek 語意可參考 [PyAV container API](https://pyav.basswood.io/docs/stable/api/container.html#av.container.InputContainer.seek)。正式與精簡安裝都固定 `av==17.0.1`；分析用 OpenCV 版本保持原本的固定版本。

## 快取與驗證邊界

索引存放於本機暫存目錄 `surgeryocr-frame-index`，依影片路徑、大小、修改時間及 PyAV 版本失效。第一次載入需要讀取媒體索引，會顯示等候狀態；後續可使用快取。快取損壞會重建，畫面快取最多保留少量影格。這些操作不修改影片或既有分析 JSON。

`tests/check_indexed_video.py` 使用帶 700 毫秒時間戳間隔的 H.264 測試片，將隨機跳轉與順序解碼逐像素比較；也涵蓋跨間隔定位、播放游標、片尾、損壞快取與來源更新。GUI 測試涵蓋實際時間軸幾何、拖曳前後一致性、表格與時間軸跳轉、切換影片時的階段資料，以及定位失敗時清除舊畫面。

實際兩部影片的重現、修正與 GUI 證據位於本機忽略追蹤的 `build/ui-timing-audit/`。全批來源核對會對每個 STAGE 的起訖影格重新比對範本、核對影格數並比較分析檔 SHA-256；這驗證的是 STAGE 邊界與資料完整性，不代表每一筆 OCR 數值都經過人工複核。

## 2026-10-24 完成核對

已完成全部 95 部：共 2,706 個 STAGE 起訖點全部相符，沒有解碼或影格數不一致，所有原始分析檔 SHA-256 保持不變。另有一部沒有 STAGE 事件的短片，已完整順序解碼 1,143 幀，確認無 STAGE 範本命中。

`build/ui-timing-audit/stage-source-audit.json` 保存逐部結果；`checkpoint-summary.json` 保存完成摘要，`complete=true`、`paused_by_user=false`。

GUI 實際案例紀錄 `gui-final-case-a.json` 確認畫面、表格和滑桿均為第 2287 幀／78.665 秒，畫面與順序解碼像素完全相同。後續 `gui-followup-check.json` 再以兩部真實影片驗證表格、滑桿、時間軸、鍵盤、播放、ROI 預覽與首幀清理，沒有 Tk 回呼錯誤，所有比較畫面均與順序解碼相同。

複查也修正了舊診斷把所有畫面與最大編號範本比較、固定使用機型 1/2 與錯誤門檻的問題。`utils/viewer_reference.py` 改為依目前幀的分析紀錄，讀取正確機型與對應編號的參照，使用對應的二值化／RGB 子區域及門檻。參照不存在時顯示「未比對」，沒有紀錄的幀也不會被誤報為分析失敗。播放中只顯示當前分析紀錄，不執行連續的參照驗證。

播放時 ROI 前後幀預覽會同步更新；回到首幀或切換影片會清除舊預覽。滑桿滑鼠放開或鍵盤調整放開後會提交定位，並把「定位預覽」更新成「已定位」。完整測試共 151 項通過；本次分析 golden 回歸 4 部影片均以 `--rtol 0` 與原有輸出完全一致，執行時間 974.3 秒。
